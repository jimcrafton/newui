## Gotchas learned
- Icon SVGs must not carry `width`/`height` (renderSvgFile would draw at that size, clipping when smaller); `ToolbarButton::iconSize` (new) sets the raster size.
- In `.newui`, put `model` before `selectedIndex` on a DropDownList or the selection is dropped.
- Labels in a row need an explicit width or they lay out at 0.
- `.newui`: the reader merges file element *i* of a collection into the existing child *i*. A `ScrollView`'s `childViews[0]` is its internal viewport
  (content nests inside it). Put `bounds` before `layout`/`childViews`. `ToolbarSeparator.horizontal` must match the toolbar and be read before
  `desiredSize`. A `SegmentedControl` in a centering row needs an explicit width. Bare `SubView` needs `visible: true`.
- Bash tool chokes on some heredocs (apostrophes); write scripts with the Write tool. In C++ edits via Python, `\n` inside printf strings gets mangled -
  use Edit.
- IDE clang diagnostics on these files are include-path noise; the MSBuild result is authoritative.

## Appearance panel - scope and progress (agreed with the user)
Goal: an object's look is an ordered stack (bottom to top) of fills, strokes and effects, each with opacity / blend mode / visibility; the Appearance panel edits it; Graphic Styles save it.
- **A1 model + rendering - DONE (113 tests, `--check-tools` pass):** `AppearanceItem {kind Fill|Stroke, visible, opacity, blendMode, paint, strokeWidth, strokeOptions}` in sketchobject.h; `SketchObject::appearance()/setAppearance()`. Invariant: every object has at least one fill and one stroke (the *primary* ones, possibly paint None); `fill()/stroke()/strokeWidth()/strokeOptions()` and their setters are shortcuts to the first fill / first stroke, so the Color/Stroke panels, gradient tool and width tool are unchanged. `paint()` walks the items bottom to top (item blend, else the object's; alpha = object opacity x item opacity); hit-test/bounds consider every visible item. `StyleState {id, items, opacity, blendMode}` (+ `of()`, `applyTo()`) is the undo snapshot.
