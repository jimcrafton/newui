## Code structure (MVC; main.cpp was split up 2026-10-16)
`main.cpp` (~130 lines) only parses the command line, loads `Resources/sketch.newui`, builds the model and the window controller and runs. Everything else has one home:
- **Model:** `SketchDocument` / `SketchObject` (the artwork, selection, undo history, color mode, graphic styles). No UI knowledge.
- **Views:** `CanvasView`, `StylePanel`, `GradientBar`, `SwatchGrid`, `PagePreview`, plus the menus / toolbars / palette / status bar declared in `sketch.newui` (generated by `tools/gen_newui.py`).
- **Controllers** (all derive from `newui::Controller` and observe the document through a plain reference, like manyrows' `SpreadsheetController`): `SketchDocumentController` (File: New / Open / Save / Document Setup, the questions and dialogs, Open Recent list), **`SketchCommandController`** (`sketchcommands.h/.cpp`: every other command under a string id - `edit.undo`, `arrange.bringToFront`, `object.flipHorizontal`, `view.toggleGrid`, `color.cmyk`, `file.exit`... - with `enabled()` and the Undo / Redo labels; the ONE place a command is written), **`SketchWindowController`** (`sketchwindow.h/.cpp`: binds views to the model and controllers, one `bind...()` method per concern - file events, zoom, menus, toolbar buttons, view check marks, Undo / Redo state, color mode, status bar, tool palette, style panel, shortcuts). Menu items and toolbar buttons are rows in two tables (`kMenuBindings`, `kButtonBindings`) that name a command id; the tool palette is one table `kTools` (button, tool, status hint) so a NEW TOOL = one row there + the palette button in gen_newui.py.
- **Self-checks:** `sketchchecks.h/.cpp` (`runToolChecks(window)`), the old `--check-tools` code as one method per area (`checkPalette`, `checkCommands`, `checkColorPanel`, `checkGradientTool`, `checkAppearancePanel`, `checkEffects`, `checkGraphicStyles`, `checkDrawingTools`, `checkLiveShapes`, `checkTextTool`, `checkWidthTool`, `checkHandleCursors`, `checkSnapping`, `checkOpenRecent`); 202 checks, `checkCommands` is new and covers the command / menu / status-bar wiring. To add a command: register it in `SketchCommandController::add...Commands()`, add a row to a binding table, done.

## Gotchas learned
- Icon SVGs must not carry `width`/`height` (renderSvgFile would draw at that size, clipping when smaller); `ToolbarButton::iconSize` (new) sets the raster size.
- In `.newui`, put `model` before `selectedIndex` on a DropDownList or the selection is dropped.
- Labels in a row need an explicit width or they lay out at 0.
- `.newui`: the reader merges file element *i* of a collection into the existing child *i*. A `ScrollView`'s `childViews[0]` is its internal viewport
  (content nests inside it). Put `bounds` before `layout`/`childViews`. `ToolbarSeparator.horizontal` must match the toolbar and be read before
  `desiredSize`. A `SegmentedControl` in a centering row needs an explicit width. Bare `SubView` needs `visible: true`.
- Bash tool chokes on some heredocs (apostrophes); write scripts with the Write tool. In C++ edits via Python, `\n` inside printf strings gets mangled -
  use Edit.
- IDE clang diagnostics on these files are include-path noise; the MSBuild result is authoritative.

## Group / Ungroup (done; 112 model tests + `--check-tools` pass; NOT yet tried by hand)
- Design: NOT a tree. Groups are tags on the flat list: `SketchObject::groups()` = ids of the groups it is in, outermost first (`SketchDocument::newGroupId`); members are kept adjacent in z-order. This kept rendering/transforms/hit-test/undo untouched.
- `SketchDocument::groupSelection()` (>= 2 objects; members gather where the topmost was; new outermost group), `ungroupSelection()` (pops the outermost id; objects stay selected), `canGroup/canUngroup`, `withGroupMembers(ids)`. Both undoable. Menu Object > Group / Ungroup, the toolbar group/ungroup buttons, Ctrl+G / Ctrl+Shift+G (canvas).
